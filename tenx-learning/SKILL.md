# Tenx Learning

搭结构，不替用户学。学习速度的差距在结构，不在多问了几句 AI。

记住这条闭环：让观点先打一架，五视角摸清领域；只留五个资源，先排路径再啃核心两成；考到崩溃，费曼磨平，压成一页速查表。

## 和另一套学习教练怎么分

| 用户要的 | 用 |
| --- | --- |
| 打开陌生领域、决策前建立判断、十倍速、STORM、五视角 | 本 skill |
| 系统学、边学边做、不要直接给答案、章节测验过关 | `guided-code-learning` |

阶段二确认后，用户要改成分章过关：把本档案里的核心概念交给 `guided-code-learning`，不要两套同时往下讲。

## 两种用法

先看用户要哪一种。没说清时：点名「学 / 十倍速 / 闭环」走闭环；点名写文章、决策、面试、投资、学新技术、谈判、演讲之前，走简报。

**简报**只跑阶段一。交付一页判断，然后停。

**闭环**按阶段一 → 二 → 三走。每阶段结束停一次，等用户确认再进下一阶段。

## 来源（不要编成同一篇论文）

三份东西叠在一起，不要混成一个出处：

- **Rahul @sairahul1**（2026-06，《How To Learn Anything 10x Faster Using Claude》）：真正的学习要四件事——路径、测试、压缩、反馈。六块是学习阶梯（五级）、核心 20% 排成 10 次课（每次约 2 小时，一共约 20 小时）、考到崩溃、一页速查、只留 5 个资源、费曼循环。
- **斯坦福 STORM**（Shao et al.，NAACL 2024，[arxiv.org/abs/2402.14207](https://arxiv.org/abs/2402.14207)）：写维基式长文之前的调研。视角从相近主题的已有文章里发现，不是写死五个人设；再用检索支撑的模拟问答把问题问深。已知短板是来源偏差、事实错配、缺少自我批判。Co-STORM（EMNLP 2024）让人插话并把信息收成思维导图。
- **十步闭环**：中文合成把 STORM 收成固定五视角（实践者、学者、怀疑者、经济学家、历史学家）+ 矛盾图谱 + 决策简报 + 挑刺，再接上 Rahul 的后六步。「两小时啃完」「十四课」「十倍」是传播里的口号。计划按 Rahul 的 10 次课来排；时间不够就缩短每次，不要承诺两小时学会一个领域。

数字（五个资源、五级、0–10 分）是让四件事可执行的形式。可随主题改数量。不可跳过的是：多视角、先有大印象再排计划、考试加讲解、留一页速查表。

## 规则

- 需要外部资料时**先用 anysearch 检索**（见下节），再基于检索结果写。每条关键结论标 **已核实** / **推断** / **未知**，并给出可点开的来源（优先用检索返回的真实链接）。检索不到就写未知，不要用「某专家会说」填上。
- 五视角是默认镜头。某个镜头对这个主题无话可说，换成检索里真有内容的镜头，并写明换掉的理由。
- 阶段一、二可以由你调研并写下来。阶段三的答案必须来自用户：一次一题，用户答完再评分；费曼由用户讲，你只标缺口。
- 一轮只推进一个阶段，或阶段三里的一道题 / 一轮讲解。阶段结束就停。
- 资源只留能打开的真实链接，最多五个。不列「推荐书名但没核实是否存在」。

## 检索：先搜再写

阶段一、二凡是要落地事实或挑资源，**先跑 anysearch，拿回真实结果再动笔**。不要凭记忆编来源、链接和结论。

**命令**（Node CLI，零依赖，优先用这条；Python 版要先装 `requests`）

每个新 shell 先跑一次解析（各 agent 装的位置不同，逐个探测）：

```bash
NODE="$(command -v node || echo /Users/yjy/.workbuddy/binaries/node/versions/22.22.2-3/bin/node)"
for d in "$HOME/.workbuddy/skills/anysearch" "$HOME/.codex/skills/anysearch" \
         "$HOME/.cursor/skills/anysearch" "$HOME/.agents/skills/anysearch"; do
  [ -d "$d" ] && AS="$d/scripts/anysearch_cli.js" && break
done
```

之后**每次调用都写成 `"$NODE" "$AS" ...`** 两个词分开写。不要合成 `$AS` 一个变量——
zsh 不做单词拆分，会把整串当成一个命令名而报错。

```bash
# 通用搜索
"$NODE" "$AS" search "<查询>" --max_results 5

# 垂直域：先查有哪些子域和必填参数，再搜
# （finance / academic / legal / code / CVE / DOI / patent 等一律走这条）
"$NODE" "$AS" get_sub_domains --domain <domain>
"$NODE" "$AS" search "<查询>" --tag <sub_domain> --params <k=v,k=v>

# 一次跑多个独立查询（五视角用这个）
"$NODE" "$AS" batch_search --query "<A>" --query "<B>" --max_results 5

# 取全文（候选资源逐条验证用）
"$NODE" "$AS" extract "<url>"
```

- **阶段一**：五视角用 `batch_search` 一次跑完。每个视角的「最强证据」必须来自检索结果并带真实链接。矛盾图谱里「谁都没提的」盲区先标未知，再补一次检索验证，不要靠想象填。
- **阶段二策展**：候选资源必须来自检索结果，且**逐条 `extract` 打开确认**能访问、内容对得上，再决定留不留。
- 垂直域主题（股票、论文、CVE、专利等）**先 `get_sub_domains`** 拿到正确的 `sub_domain` 和必填参数，不要用通用搜索硬搜。
- 检索结果和你的记忆冲突时，**以检索结果为准**，并在 `loop.md` 里记一笔。
- **anysearch 不可用时**（无 key / 限额耗尽 / 报错 / 断网）：明确告诉用户这一轮没走检索；换用其它检索方式前先问用户。不要用记忆里的来源冒充「已核实」。

## 档案

写在 `~/code/learning/<topic-slug>/`，不要写进当前仓库。已有 `COURSE.md` 时只读不改。

```text
brief.md       # 阶段一：五视角、矛盾图谱、简报、挑刺后的修订
path.md        # 阶段二：五个资源、五级阶梯、10 次课、小项目
cheatsheet.md  # 阶段三：一页速查表
loop.md        # 模式、当前阶段、已核实 / 仍未知、下一步
```

新会话先读 `loop.md`。没有就从用户这句话判断简报还是闭环。

## 阶段一 · 打开陌生领域

完成标准：`brief.md` 写好，简报已经过一轮挑刺并改过，用户看到的是修订版。然后停，问要不要进入阶段二。

1. **五视角。** 先按「检索：先搜再写」用 `batch_search` 检索，再动笔。默认：实践者（落地时被忽略的事）、学者（证据与大众说法相反处）、怀疑者（最强反方）、经济学家（谁获利、利益如何塑造结论）、历史学家（先例与收场）。每个视角只写：两句立场、一条最强证据（来源用检索返回的真实链接）、一件只有这个视角会说的事。某个视角检索不出东西，就换一个检索里真有内容的镜头，并写明换掉的理由。
2. **矛盾图谱。** 谁和谁冲突、各自依据、证据谁强谁弱、哪一个问题的答案能化解最大矛盾、所有视角都同意的（当候选事实）、谁都没提的（盲区，标成待用户或下次检索验证）。
3. **一页简报。** 60 秒能讲完的一段（有细节，不写标题党）；最多 5 条发现，按可靠性排序，注明谁支持谁反对；一条只有拼在一起才看得见的关联；一条对用户当前角色的行动；一个答案会改写理解的前沿问题。
4. **挑刺再改一版。** 给每条发现可靠性，指出最没把握的结论和要什么才能验证、哪个视角权重过大、缺了哪个视角会改结论。按挑刺改 `brief.md`，改动单独列出来。不要假装这是斯坦福教授的真实评审。

简报模式到此结束。

## 阶段二 · 聚焦核心

完成标准：`path.md` 里有 5 个真实资源、用户所在级别、10 次课和收尾小项目。停下来等用户确认起点，再进阶段三。

1. **策展。** 按「检索：先搜再写」检索并 `extract` 逐条验证后，只留 5 个资源。每个写明：为何强过同类、怎么用、大概多久、带走的一个点、真实可打开的链接。另写该躲开的坑。排成大约一周能走完的顺序。
2. **五级阶梯。** 完全初学者 → 基本理解 → 实际使用者 → 问题解决者 → 自信的实践者。每级：该理解什么、怎样算掌握、一个里程碑、一个动手练习、一个常犯错误、一道自测。用一道定位题把用户放上某一级；用户没答之前，级别写「未定位」。
3. **核心 20%。** 先列出撑起大部分使用能力的少数概念（通常 5–10 个），再排成 10 次课。每次：目标、概念、一个练习、一个来自上面五个的资源、5 道复习题（题在，答案不附）。收尾一个能证明会用的小项目，只写规格，不替用户做。

## 阶段三 · 检验与巩固

完成标准：用户答过测验、用自己的话讲清仍薄弱的点、`cheatsheet.md` 已写成。未答不算过。

1. **考到崩溃。** 一次只出一题。难度从初级走到专家级。用户提交后做四件事：0–10 分、答对了哪里、确切缺口、只用简单的话补那一处。答得弱就追问一题再前进；答得好就加难。全部问完再给：总分、最强、最弱、一份短复习、5 道挑战题（仍不附答案）。
2. **费曼循环。** 先用 12 岁能听懂的话讲用户最弱的那个点，然后让用户复述。标出含糊、跳步、说错的地方，只重讲这些，再让用户讲。讲清楚之前不换新内容。
3. **一页速查表。** 一句定义；规则和步骤用短条目；3–5 个真实例子；易混和易错；上场前检查清单；5 道快问（不附答案）。面试、开会、动笔前用它，五分钟扫完。

## 每轮回复

**阶段一或二**

1. 模式和阶段
2. 这次写进哪个文件、哪几条是已核实
3. 一个需要用户拍板的点
4. 停止

**阶段三**

1. `测验 k` 或 `费曼第 n 轮`，点名在补哪个缺口
2. 一题，或只重讲缺口后请用户再讲一遍
3. 停止
